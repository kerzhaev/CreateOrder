# Дизайнерская компоновка мастера зачисления V2

Дата: 28.08.2026
Состояние: завершено, V2 является рабочей формой
Исполнитель этапа: Codex; ручная геометрия подтверждена владельцем 28.08.2026

## Цель

Создать рядом с действующей `frmEnrollmentWizard` отдельную форму `frmEnrollmentWizardV2`, в которой текущая визуальная структура мастера сохранена как design-time контролы MSForms. Владелец должен получить возможность перемещать и изменять размеры элементов мышью в конструкторе VBA без диалога о числовых координатах.

## Границы этапа 1

- Действующая `frmEnrollmentWizard`, команда ленты и рабочий сценарий зачисления не меняются.
- V2 служит только макетом для ручной компоновки; бизнес-логика будет подключена после сообщения владельца о завершении разметки.
- Исходная геометрия, подписи, контейнеры и порядок вкладок V2 должны соответствовать текущей runtime-форме.
- У каждого design-time контрола должно быть стабильное уникальное имя и запись в манифесте соответствия исходному контейнеру/контролу.
- Код V2 не должен программно изменять `Left`, `Top`, `Width` или `Height`.
- Форма экспортируется и хранится парой `frmEnrollmentWizardV2.frm` / `frmEnrollmentWizardV2.frx`; `.frx` создаётся только Excel/VBE и не редактируется вручную.
- Перед добавлением V2 в `CreateOrder.xlsm` создаётся резервная копия, Excel должен быть закрыт.

- [x] Экспортировать `.frm/.frx`, сохранить манифест соответствия и автоматически проверить тип формы, дерево контейнеров, количество контролов и отсутствие влияния на V1.
- [x] Открыть V2 в конструкторе VBA, визуально подтвердить возможность ручного перемещения и обновить документацию для передачи владельцу.

## Приёмка этапа 1

1. `frmEnrollmentWizardV2` присутствует в `CreateOrder.xlsm` как UserForm Type 3.
2. V1 по-прежнему является формой рабочего сценария; Ribbon и обработчики не ссылаются на V2.
3. V2 содержит семь вкладок и статические элементы текущей формы, доступные в конструкторе VBA.
4. V2 можно открыть/предпросмотреть без создания runtime-контролов и без изменения данных книги.
5. Экспортированная пара `.frm/.frx` и манифест находятся в `CreateOrder.xlsm.modules`.
6. В документации явно указано: следующий шаг выполняет владелец, после чего Codex подключает логику и обновляет тесты под имена V2.

## Не входило в этап 1

- Переключение рабочей кнопки на V2.
- Перенос бизнес-логики, событий, локализации и загрузки данных в V2.
- Изменение координат по вкусу владельца.
- Удаление или переименование V1.
