# P2 — Центр целостности кадровых данных

## Цель

Добавить read-only проверку служебных кадровых реестров книги. Проверка должна находить ссылки на отсутствующие записи, дубликаты и противоречия между событиями, снимками, текущим состоянием, назначениями выплат, документами и нормативными справочниками, не исправляя данные автоматически.

## Границы и запреты

- Первая версия только читает книгу и возвращает детерминированный список находок.
- Никаких `Select`, `Activate`, `MsgBox`, записи в ячейки, создания листов или вызова `HealWorkbookStructure`.
- Логи пишутся только через `Debug.Print` и не содержат ФИО, табельных/личных номеров, путей к файлам или текста оснований. Допустимые события: `INFO integrity-scan-complete`, `WARN integrity-finding`, `ERROR integrity-scan-failed`.
- Каждая находка имеет поля: `Severity`, `Category`, `EntityType`, `EntityID`, `Message`, `SuggestedAction`. Идентификатор в выводе обезличивается; диагностические сообщения не включают PII.
- Исправление возможно только отдельным будущим действием оператора после просмотра списка; этот этап не реализует autofix.

## Реестр и категории проверок

| Category | Проверка | Минимальная находка | Severity по fixture |
| --- | --- | --- | --- |
| `SCHEMA` | Наличие обязательного листа/заголовка | отсутствует лист или header | ERROR |
| `IDENTIFIER` | Непустые идентификаторы и уникальность | пустой или повторный `EmployeeID`, `EventID`, `SnapshotID`, `AssignmentID`, `DocumentID`, `ActID` | ERROR |
| `EVENT_EMPLOYEE` | Событие → `Employees` | `PersonnelEvents.EmployeeID` не найден | ERROR |
| `EVENT_SNAPSHOTS` | Событие → before/after snapshots | отсутствует ссылка или snapshot с другим `EventID`/`EmployeeID` | ERROR |
| `SNAPSHOT_LINKAGE` | Снимок → событие/сотрудник/вид | неверный `SnapshotKind`, отсутствует событие или сотрудник | ERROR |
| `ASSIGNMENT_LINKAGE` | Назначение → сотрудник/событие/НПА | отсутствует employee/event либо `ActID` не найден | ERROR |
| `DOCUMENT_LINKAGE` | Документ → событие/файл | отсутствует event или непустой путь не существует | WARNING |
| `CURRENT_STATE_LINKAGE` | `EmployeeCurrentState` → employee/`LastEventID` | отсутствует сотрудник или событие последнего изменения | ERROR |
| `CHRONOLOGY` | Даты событий и снимков | `EffectiveDate < EventDate`, snapshot создан раньше события, даты цепочки нарушены | ERROR |
| `ACTIVE_PAYMENTS` | Активные выплаты и исключение | активная выплата у неактивного сотрудника или после `EXCLUSION` | ERROR |
| `STAFF_LINK` | Связь с листом `Штат` | подтверждённая ссылка не имеет строки/личного номера | WARNING |
| `LEGAL_REFERENCE` | НПА и классификация | `ActID` отсутствует в `LegalActs`, активное назначение без основания | ERROR |

Пустые необязательные поля не считаются дефектом. Для файлового пути проверяется только существование, без раскрытия пути в сообщении. Неизвестные дополнительные строки/столбцы не удаляются и не изменяются.

## Контракт VBA

Новый стандартный модуль `mdlPersonnelDataIntegrity.bas` предоставляет:

- `Public Function ScanPersonnelDataIntegrity() As Collection` — коллекция словарей с шестью полями находки;
- `Public Function BuildPersonnelDataIntegrityReport() As String` — детерминированный текст для формы/теста, отсортированный по `Severity`, `Category`, `EntityType`, `EntityID`;
- `Public Function PersonnelDataIntegritySummary() As Object` — счётчики `Sheets`, `Rows`, `Findings`, `Errors`, `Warnings` без PII.

Сканер не вызывает процедуры, меняющие книгу. Ошибка чтения возвращает одну `ERROR` находку категории `SCAN` и пишет `ERROR integrity-scan-failed`.

## UI P2.3

Design-time `frmDataIntegrityCenter` содержит кнопку «Проверить», фильтры severity/category, read-only многострочный список, сводку и постоянное пояснение «Исправление не выполняется». Кнопки просмотра/закрытия не изменяют реестры. Все подписи проходят через `ModuleLocalization` и лист `Localization`; Ribbon вызывает отдельный обработчик без перехода на служебные листы.

## Fixture и приёмка

`tools/Test-PersonnelDataIntegritySafe.ps1` создаёт disposable-копию книги и добавляет ровно по одному дефекту каждой категории из таблицы. До и после сканирования сравниваются значения и SHA-256 шести кадровых реестров и листа `Штат`; ожидаются все категории, правильные уровни и нулевая мутация. Отдельно проверяются чистая копия (0 находок), повторный скан и отсутствие PII в `Debug.Print`/отчёте.

После адресной проверки модуль и форма импортируются в `CreateOrder.xlsm` только после backup. Затем повторяются кадровые V2/E2E, полный acceptance и designer/ribbon проверки. Ручной визуальный просмотр формы остаётся owner gate.

## Открытые вопросы

- Автоисправление структуры и ссылок сознательно отложено; до отдельного решения владельца центр только диагностирует.
- Для неоднозначной связи со `Штат` показывается предупреждение и предлагается ручная проверка, автоматическое связывание запрещено.
