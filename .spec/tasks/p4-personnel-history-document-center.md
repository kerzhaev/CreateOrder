# P4.1 — Контракт центра истории и документов сотрудника

**Дата:** 29.08.2026  
**Статус:** спецификация утверждена для P4.2–P4.4  
**Зависимость:** P2 и P3 завершены.

## 1. Цель

Дать оператору единое окно поиска сотрудника и просмотра хронологии кадровых событий, снимков, назначений выплат, зарегистрированных документов и синхронизаций со `Штат`, не используя лист `PersonnelHistory` как промежуточное хранилище. Просмотр не должен менять книгу.

## 2. Read-model

Публичный `BuildPersonnelHistoryCenterReport(query, Optional selectedEventID, Optional selectedDocumentID)` читает только:

- `Employees` и `EmployeeCurrentState`;
- `PersonnelEvents` и `PersonnelStateSnapshots`;
- `PaymentAssignments`;
- `DocumentRegistry`;
- `StaffStateSyncLog` (если лист существует).

Поиск принимает точное значение `EmployeeID`, личного номера, табельного номера или ФИО. Ноль совпадений и неоднозначное совпадение — явная ошибка без записи. Отчёт детерминированно сортируется по дате события, затем по `EventID`; значения даты форматируются одинаково.

## 3. UI-контракт

Design-time `frmPersonnelHistoryCenter` содержит статические контролы для:

- поиска сотрудника и кнопки `Найти`;
- явного `EventID` и `DocumentID` для действий;
- read-only multiline хронологии со штатными scrollbars;
- действий `Открыть документ`, `Повторить экспорт`, `Подготовить корректировку`;
- пояснения, что поиск/просмотр не меняют реестры, и кнопки `Закрыть`.

Никаких `Controls.Add` и присваивания `.Left/.Top/.Width/.Height` во время открытия формы. Все новые подписи проходят `ModuleLocalization` и лист `Localization`.

## 4. Явные действия и границы записи

- `Найти` и фильтрация — read-only, не создают листов и не очищают `PersonnelHistory`.
- `Открыть документ` проверяет, что `DocumentID` принадлежит выбранному сотруднику/событию и файл существует; отсутствующий файл даёт WARN и не реконструируется.
- `Повторить экспорт` разрешён только для сохранённого события выбранного сотрудника и явно вызывает существующий экспортёр; результат регистрируется обычным `DocumentRegistry`-контрактом.
- `Подготовить корректировку` разрешено только для выбранного события и вызывает существующую подготовку correction; просмотр не запускает её автоматически.

## 5. Логирование и приватность

Логи: `INFO history-search`, `INFO history-document-opened`, `INFO history-export-requested`, `INFO history-correction-prepared`, `WARN history-document-missing`, `ERROR history-failed`. В логах только количества, типы действий и коды ошибок; ФИО, личные/табельные номера, пути файлов и текст оснований не выводятся.

## 6. Приёмочная матрица

| Fixture | Ожидание |
|---|---|
| один сотрудник, два события, snapshots, assignment, document, sync log | report содержит все разделы в детерминированном порядке |
| запрос по EmployeeID/личному/табельному/FIO | один и тот же EmployeeID |
| ноль и два совпадения | ошибка поиска без мутации |
| документ отсутствует | WARN/ошибка действия, файл не создаётся |
| документ существует | действие возвращает путь/открывает файл только по кнопке |
| повторный экспорт | создаёт обычный экспортный артефакт только после явного клика |
| подготовка корректировки | заполняет correction input только после явного клика |
| scan/search/close | хеши registry sheets не меняются |
